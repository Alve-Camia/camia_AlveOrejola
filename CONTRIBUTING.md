# Project Contributions

## Overview

> [!IMPORTANT]
> The following CONTRIBUTING.md is in its "mostly incomplete" state. It's <strong><i>not a required file</i></strong> for the CS 2, year-long project. Thus, the file will currently serve as a disclaimer for those not part of the project, but have seen this repository.

### Project Status
This is a CS (Computer Science) 2 project for the S.Y. (School Year) 2025-2026. The school year has ended, and the project has been submitted for the CS 2 subject. Even though the coding project will receive updates (as will the documentation), the student developers <strong><i>will not</i></strong> accept direct code contributions to the project's development.

### Reasons:

- This isn't an open-source project, as implied earlier.</li>
- We, the student developers, have limited experience with community-related contributions (as well as branch management).
- The project is near the end of its lifecycle.</li>
- Academic Integrity (Teachers or Grades may view external aid/contributions as academic dishonesty, especially if it's a direct contribution).

## Contribution Limitations

The following are the specifics of what will not be accepted:

For Pull Requests involving:

- Feature Implementation
- Bug Fixes / Patching
- Refactors
- Security Improvements
- Automated Tests
- Maintenance & Tooling

> [!TIP]
> Notice how documentation is not listed here, meaning that pull requests involving documentation __**can**__ be accepted.

## How to Contribute

If you would like to provide feedback or suggestions to this project, feel free to write a [GitHub issue](https://github.com/Alve-Camia/camia_AlveOrejola/issues) in this GitHub repository, so long as you don't directly propose code snippets/portions.

## Feedback Guidelines

1. It is recommended to use the issue templates, as it gives us, the student coders, sufficient information to address the issue.
2. As much as possible, be as concise as possible on the issue you're reporting.
3. Check that the issue you're reporting hasn't been made by someone else already.
4. Please do not bloat the GitHub issues with non-helpful/nonsensical issue reports.

## Final Note

Regardless of contributions, thanks for your interest in the project development. Submitted feedback via GitHub issues or pull requests may not be immediately reviewed/resolved, as only 2 people are working on this.

> [!TIP]
> If needed, you may fork this GitHub repository to add specific features for your workflow.
